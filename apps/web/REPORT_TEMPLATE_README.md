# 报告模板系统说明

## 概述

报告系统现在支持从外部 Markdown 文件加载报告内容模板，将显示内容与代码逻辑分离，便于维护和更新。

## 目录结构

```
apps/web/public/reports/
  ├── DZ01V_L2_E110.3_N29.2_20251225031144.md  # 张家界市数据源报告模板
  └── [其他产品ID].md                           # 其他数据源报告模板
```

## 报告模板格式

每个报告模板是一个 Markdown 文件，文件名为产品ID（Product ID）。

### 模板结构


## 工作原理

### 1. 报告生成流程

1. 用户在报告页面选择反演数据后点击"生成报告"
2. `generateReport()` 函数被调用
3. 根据数据源的产品ID，调用 `parseReportTemplate(productId)` 加载对应的 `.md` 文件
4. 解析 Markdown 内容，提取各个章节和统计数据
5. 将模板数据与动态数据（日期、区域名称等）合并
6. 生成完整的报告对象并保存到数据库

### 2. 模板解析器 (`report-parser.ts`)

#### 主要函数

```typescript
// 解析报告模板
export async function parseReportTemplate(productId: string): Promise<ReportTemplate | null>
```

**参数**: 
- `productId`: 产品ID（文件名前缀，不含 .md 后缀）

**返回值**:
- 成功: 包含所有解析数据的 `ReportTemplate` 对象
- 失败: `null`

#### 解析内容

解析器会从 Markdown 文件中提取：

1. **概述部分** (`## 概述`)
   - 质量分数（从"综合指数为XX分"提取）
   - 质量等级（从"质量等级为"XX""提取）
   - 完整的概述文本

2. **数据源信息** (`## 数据源信息`)
   - 产品ID
   - 卫星平台
   - 传感器
   - 采集日期
   - 影像范围（自动解析经纬度）
   - 监测面积

3. **指标分析** (`## 指标分析`)
   - 有机质含量
   - 土壤含水量
   - 盐渍化程度
   - 每个指标的描述和统计数据

4. **建议措施** (`### 建议措施`)
   - 提取所有编号的建议项

### 3. Report.vue 集成

```typescript
// 导入解析器
import { parseReportTemplate } from '@/utils/report-parser'

// 异步生成报告
const generateReport = async (type: 'single' | 'timeseries', data?: any): Promise<ReportData> => {
  // 获取产品ID
  const productId = 'DZ01V_L2_E110.3_N29.2_20251225031144'
  
  // 加载并解析模板
  const template = await parseReportTemplate(productId)
  
  if (template) {
    // 使用模板数据
    return {
      // ... 合并模板数据和动态数据
    }
  }
  
  // 模板加载失败时的默认处理
  return { /* 默认报告数据 */ }
}
```

## 添加新的报告模板

### 步骤

1. 在 `apps/web/public/reports/` 目录下创建新的 `.md` 文件
2. 文件名使用产品ID（例如: `DZ01V_L2_E110.5_N29.5_20250101.md`）
3. 按照上面的模板结构编写报告内容
4. 在 `Report.vue` 的 `generateReport()` 函数中，根据实际的数据源动态获取 `productId`

### 示例：动态获取 productId

```typescript
const generateReport = async (type: 'single' | 'timeseries', data?: any): Promise<ReportData> => {
  if (type === 'single' && data) {
    // 从数据源获取产品ID
    const productId = data.metadata?.productId || 'default_template'
    const template = await parseReportTemplate(productId)
    // ...
  }
}
```

## 注意事项

### 1. 文件放置位置

模板文件必须放在 `public/reports/` 目录下，因为：
- `public` 目录下的文件可以通过 HTTP 直接访问
- 使用 `fetch('/reports/xxx.md')` 可以加载文件内容

### 2. Markdown 格式要求

- 必须使用标准的 Markdown 标题语法（`##`、`###`）
- 统计数据必须使用列表格式（`- 平均值: XXX`）
- 建议措施必须使用编号列表（`1. **【标题】** 内容`）

### 3. 字段提取规则

解析器使用正则表达式提取数值：
- 质量分数：`/综合指数为(\d+)分/`
- 质量等级：`/质量等级为"([^"]+)"/`
- 经纬度范围：自动解析 `北纬XX° ~ XX°, 东经XX° ~ XX°` 格式

### 4. 错误处理

- 如果模板文件不存在，`parseReportTemplate()` 返回 `null`
- `generateReport()` 会使用默认的简化数据生成报告
- 错误会在控制台输出，不会中断报告生成流程

## 优势

1. **内容与代码分离**: 报告文本内容独立存储，便于非技术人员编辑
2. **易于维护**: 修改报告内容不需要改动代码
3. **多数据源支持**: 每个数据源可以有独立的报告模板
4. **版本控制友好**: Markdown 文件易于进行 Git 版本管理
5. **可扩展性**: 新增数据源只需添加对应的 `.md` 文件

## 未来改进方向

1. **变量插值**: 支持在 Markdown 中使用变量占位符（如 `{{studyArea}}`）
2. **模板管理界面**: 提供可视化的模板编辑和管理功能
3. **多语言支持**: 根据用户语言偏好加载不同语言的模板
4. **模板验证**: 添加模板格式验证工具，确保内容完整性
5. **动态图表**: 在模板中嵌入图表配置，自动生成可视化内容
